# S6 plan: main-chart heatmap on the GPU path (owner-approved 2026-10-01)

Drafted by a Claude Fable planning agent and reviewed by the orchestrator. The owner approved it with the decisions in section 9. It builds on `2026-09-s5-plan.md` and `2026-09-s5l-plan.md` (landed) under the product contract in `2026-09-heatmap-interaction-spec.md`. For S6 it supersedes the S6 row and the pre-B1 wording of `2026-09-gpu-heatmap-integration-plan.md`.

## 1. Goal, scope, done

**Goal.** `UnifiedGridRenderer` (UGR) draws the heatmap through `HeatmapSourceController` + `HeatmapTileNode`, fed by `SentinelStreamClientTransport`, exactly as `sentinel-lab --server` does (`libs/gui/lab/LabData.cpp`, `LabItem.cpp`). A temporary toggle keeps the legacy renderer selectable.

**Non-goals:**
- labels and walls on `binCell` (S7; labels keep reading the legacy ring);
- deletion of the legacy path (S8);
- the disk cache.

**Done, for the owner,** with `heatmap.renderer: gpu`:
- (a) the main chart pans, zooms and changes tick in one frame (lab: 16-23 ms);
- (b) live edge data age p95 < 0.6 s at 1m and 5m (lab: 464 / 597 ms);
- (c) the chart reaches $1 inside the near band, with the veil and indicator outside it;
- (d) the chart never blanks on a tf, tick or symbol switch, or on reconnect;
- (e) candles, TPO, footprint, VP, axes and paper-trade overlays still align;
- (f) cold start to the first data frame takes 1 s or less against the local server;
- (g) every setting in section 4 is live-editable and persisted;
- (h) the lab telemetry panel is a dock in the main app;
- (i) the A/B screenshots and the Windows D3D12 run pass.

## 2. Integration design

**Process-wide service.**
- Extract LabData's core into `libs/gui/render/heatmap/HeatmapDataService`, which takes a `ChunkTransport` factory. The core is:
  - the "heatmap-data" thread;
  - `ChunkFetcher`, `SpanSourceCache` and `ChunkStore`;
  - controller create/destroy;
  - the stats timer.
- `LabData` becomes a thin configurator (local or server transport), so only one implementation exists.
- In `MainWindowGPU`, create the service with a `SentinelStreamClientTransport` over `RemoteGridDataSource::streamClient()` BEFORE `remote->connectToServer()`. The transport only learns `connected` from the signal, so a late attach misses the first connect and the availability push on `subscribe`.
- Budgets come from settings.
- Multi-chart: one service, and one controller + node per UGR.

**Per-chart layer.** A new `HeatmapGpuLayer` (a QObject owned by UGR, GUI thread) is `LabItem` without view ownership. It holds:
- the controller handle;
- the latest `SpanSet`, `LiveSnapshot` and `ResolutionSummary`;
- the tick policy with its `TickKey` cache;
- `ManualTickMemory` and the offered presets;
- the settings and `HeatmapTileStats`.

It gets the symbol from `setActiveSymbol` and the tf from `setTimeframe`. In gpu mode, the view comes from `GridViewState::viewportChanged` through `postView`.

**Hosting.**
- Overlays, TPO, VP and text already take `QSGNode*` parents. In gpu mode, `ensureHeatmapRootNode` returns a plain `QSGNode` root with the `HeatmapTileNode` as its first child; legacy mode keeps the `HeatmapIntensityNode` root.
- `updatePaintNode` branches once. Gpu mode builds the node's `Frame` exactly as `LabItem` does, then renders overlays and text as today.

**Mapping.** In gpu mode, fill `TimeAxisMapping` from the viewport only:
- `drawRect` = surface bounds;
- `dataStartMs` = floor(viewStart / tf) * tf;
- `srcRect` = [colF(viewStart), colF(viewEnd)];
- `actualData*` = the view bounds;
- `tickSize` = the drawn tick.

`heatmapTickSize` in QML reports the drawn tick, so `PriceAxisModel` steps on it.

**Interaction (spec rules 1-9):**
- **Rules 1 and 9** (column = tf, 1 column/px, axis drags obey the same clamps): add optional max spans to `GridViewState`, applied inside `setViewport` and the zoom handlers. Wheel, axis drags and the Agent API then all clamp the same way. UGR sets the spans from `maxTimeSpanMs` and `maxManualPriceSpan` whenever tf, tick, mode or size changes.
- **Rules 2 and 4:** Auto/Manual, with memory per (symbol, tf), live in the layer. Presets come from `manualPresetUnits`.
- **Rules 3, 5, 6 and 7:** the node contract, unchanged (INV-085/087).
- **Rule 8:** the `crossfadeMs` setting (0 = hard switch).

Behaviour:
- **Follow-live:** keep `GridViewState::autoScroll`. In gpu mode the shift comes from `LiveSnapshot::openEndMs`, and `HeatmapStreamService::handleRenderTick` is skipped.
- **Cold start:** keep the book-top seed for the first viewport and request the view at once. The node draws the loading hatch until the newest span lands. The first price window uses `initial_price_pct`.
- **Symbol/tf switch:** the controller serial handles fallback and recent-tf. UGR must not call `clearData()` for the heatmap in gpu mode.

## 3. A/B toggle

**The toggle:** `heatmap.renderer: legacy|gpu` in `ClientHeatmapConfig`, overridable per chart at runtime (settings dialog, Agent API).

**Shared between modes:** the one `SentinelStreamClient`, the viewport, the axes, the overlays and the candles.

**Not shared:** in gpu mode the legacy band stream is muted by a new `DataProcessor::setHeatmapEnabled(false)` guard in `scheduleRecordingBand`, `requestHeatmapFetch` and `onHeatmapSliceReceived`.
- A plain `setRecordingConfig(false)` would drop the processor into legacy-slice mode, so it is not used.

## 5. Agent API

**New routes:**
- `GET /api/v1/heatmap/state` reports:
  - the renderer, tick mode/units and offered presets;
  - whether it has settled, and the drawn tf/tick;
  - the indicator text;
  - resident/GPU bytes;
  - the live version and age;
  - the controller stats.
- `POST /api/v1/heatmap/settings` takes a partial `HeatmapChartSettings` and returns an operation id, like `/viewport` does.
- `POST /api/v1/input` takes `{kind: wheel|dragStart|dragMove|dragEnd|click, target: chart|priceAxis|timeAxis, x, y, deltaY, modifiers}`. It synthesizes `QWheelEvent`/`QMouseEvent` to the heatmap dock's `QQuickView` on the GUI thread and returns an operation id. This is the synthetic input route the owner agreed S6 needs.

**Changed behaviour:**
- In gpu mode, `heatmapReceivedAtMs` comes from the live frame / snapshot time.
- Screenshots use `target=heatmap` only (FM-120).

- **Cold start:** the server path decodes on a 1-thread FIFO pool. Measure it before promising 1 s or less.

## S6a review fixes (on e76fb06, 2026-10-01)

- `_last_session` heatmap snapshots are ignored for both save and restore. Live
  per-chart settings survive a crash; only named workspaces snapshot settings.

## S6b review fixes (Codex review of 376c1e1, 2026-10-01)

Each item has a deterministic test that fails with its fix reverted (spot-checked):
- Blocker 1, teardown order: `HeatmapDataService` runs shutdown hooks before it
  deletes controllers; `HeatmapGpuLayer` forgets its controller there, and
  `~MainWindowGPU` detaches the chart first. Test `UgrGpu.TheServiceMayDieBeforeTheChart`
  (also run under Guard Malloc). Constructing the whole `MainWindowGPU` in a test
  was avoided: it reads/writes the owner's QSettings and connects to the server.
- Blocker 2, legacy resume: a gpu -> legacy flip calls
  `HeatmapStreamService::adoptViewport` (bootstrap done, initial centring
  cancelled, span/edge adopted) before unmuting. Tests `FlipToLegacyKeepsABookSeededView`,
  `FlipToLegacyAfterAGpuSymbolSwitchKeepsTheView` (recording mode, no API viewport).
- Major 3, frames: `HeatmapTileStats::wantsFrame` (budgeted uploads, crossfade, live
  paging, self-test readback); UGR queues `update()` from `afterRendering` while it is
  set. `OffscreenQuick::frameRequested()` lets the test render only on request
  (`NodeWorkGetsItsFramesWithoutOutsideRedraws`).
- Major 4, return to live: follow-live activation repositions to a live anchor that
  does not depend on the live subscription (newest live end seen, else the
  recording's committed end), in either direction; per-bucket stepping stays
  forward-only. Test `FollowLiveReturnsFromHistoryAndFromTheFuture`.
- Major 5, cold start: with no book or trade, a time-only view is bootstrapped from
  availability (placeholder price, nothing drawn); the first decoded data sets the
  price. Test `ColdStartFromTheRecordingAlone`.
- Major 6, view release: registration is tracked apart from band confirmation, so a
