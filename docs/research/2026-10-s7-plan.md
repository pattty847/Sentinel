# S7 plan: liquidity labels and walls on the GPU heatmap path (owner-approved 2026-10-01)

Drafted by a planning agent, reviewed by the orchestrator, and approved by the owner with the decisions in section 9. S7 gives the GPU renderer feature parity with legacy, so that S8 can delete the legacy path.

## 1. Scope and parity

**Goal.** With `heatmap.renderer: gpu`:
- the chart draws liquidity labels;
- `GET /api/v1/heatmap/walls` answers. The 409 `gpu_renderer` branches go (`MainWindowGpu.cpp:546-553`, `GuiApiServer.cpp:257-259`).

**Legacy has no on-chart wall markers.** Walls exist only as an Agent API scan (`HeatmapColumnWindow.cpp:53-142`). Markers are a new feature, deferred (decision 4).

**Kept from legacy:**
- Labels: one label per drawn cell, plus the Asset/USD modes.
- Walls:
  - the definition (peak dominant-side size per (cell, side) over the range, plus meanQty, first/last seen, columns, rank);
  - the JSON shape;
  - limit <= 100;
  - the 16M-cell scan limit.

**Intentionally different:**
- Labels:
  - they follow the drawn GPU tick;
  - they show spec rule 5's value (time-weighted, summed across native rows, from the source that won the fill pass);
  - veil, loading and no-data cells get no label;
  - the text size is bounded (decision 1); legacy shrank text to fit, down to 0.45.
- Walls:
  - computed at the drawn tick (an optional `tick` overrides it);
  - the default range is the chart's view (decision 3);
  - `forming` is true for the live bucket;
  - quantities are exact doubles.

## 2. Data path (chosen: CPU binning with the exact oracle)

Visible drawn cells number about 0.4-1.8 M (1080p to 4K), but cells that can carry a label are at most about 12k: 24x11 logical px or larger.

Three paths were compared:
- **(a) GPU readback.** Rejected: results arrive 2-3 frames late, it needs forced frames when idle, it stalls when the window is hidden, it gives only 15-bit codes, and it would depend on the readback that is intermittently failing (FM-126).
- **(c) A GPU reduction pass.** Rejected: same async problems, plus a new shader on five backends, and it isn't needed at about 12k cells.
- **(b) CPU binning.** Chosen. `buildCells` + `fillVeiled` produce exactly the kernel's words, states and fill rule, and `binColumn` gives exact bid/ask doubles. Walls use the same code and need no rendered frame.

Requirements for (b):
- a price-clipped compose (today `ComposeOptions` clips time only);
- a cache of composed tile windows (composition is tick-free, so a tick change re-bins only);
- stop composing near once no veiled cell remains;
- recompose from `ChunkStore::peek` using each drawn `SpanSourceKey`'s generations, because the upload images are released. Live columns stay in `LiveSourceSnapshot`.
- A sealed chunk that has been evicted is wanted again at a new "label" rank, which must respect the CPU ledger (INV-084).

## 3. Design

- **Shared draw clip.** Extract the per-picture rule from `HeatmapTileNode::layout` into a pure `drawPieces(spans, live, tf)`. The node and the label builder both call it.
- **`HeatmapCellQuery`.** One per controller, on the heatmap-data thread. Jobs run on the cache's bounded pool; the latest request wins, and stale ones are dropped by serial.
  - Input: `LabelRequest{serial, tf, tick, bucket range, bin range, SpanSet version, LiveSnapshot version}`.
  - It runs the draw clip, then the clipped compose (cached), then `buildCells`/`fillVeiled`, then `binColumn` for the winning source.
  - Output: an immutable `LabelCells` (key, grid; per cell the word, the dominant value, and preformatted USD and Asset text in fixed buffers).
  - It is published under a mutex as `latestLabels()` plus a queued `labelsChanged`.
- **Walls.** `scanWalls(query)` uses the same path at the drawn tick, under the 16M budget, from client-held chunks only. Missing buckets go to `missingColumns`; veil sets `unknownRows`. It completes through the existing async route. The JSON adds `renderer`, `tick`, and the persistence fields from decision 3.
- **Consistency.** Labels draw only from a `LabelCells` whose (serial, tf, tick) matches the picture drawn. While holding, that is the drawn tick; during a crossfade, labels hide until the new tick's result lands.

## 4. Threading, hot path, text

- **GUI thread.** The layer posts a `LabelRequest` only when its key changes, the same way as the tick request, so there is no per-frame signal. With the gate closed it posts nothing.
- **Render pass.**
  - Glyph quads are built once per `LabelCells` and text size, in cell-relative coordinates.
  - Each frame only translates them, snaps them to **device** pixels (`round(x*dpr)/dpr`; ChartTextLayout rounds to logical px today, which is wrong at 1.25x/1.5x), and culls them into a reserved vector.
  - No `QString` per label per frame.
- **MSDF.** Reuse `ChartTextAtlas` (Roboto Mono, 64 px, pxRange 4) and `ChartTextRenderer::submitGlyphs`. A density rule keeps glyphs under the 48k cap.

## 5. Update cadence

| Event | What reruns |
|---|---|
| Pan or zoom inside the cached window | Layout only |
| Bucket or bin range changes | A new request (cached compose, then bin) |
| Tick change | Bin only |
| Live version | The live window |
| tf or symbol change | The serial drops old jobs |

## 6. Tests

1. **Core:**
   - the clipped compose equals the unclipped one on the window rows;
   - `drawPieces` equals the node's pieces;
   - `LabelCells` words equal `fillVeiled(buildCells...)`;
   - `encodeSize(value)` equals the code at 1m/5m/1h and $1/$5/$10, with gaps, grid changes and the E/L clip.
2. **GPU parity (Metal; skips without a device):** `HeatmapCellCapture` readback of the drawn bins equals the label words across the fill pass, the live bin, holds and crossfades.
3. **Walls parity:** legacy `ColumnWindow::captureWalls` and `scanWalls`, run at the legacy band tick on the same synthetic recording, agree.
4. **Codec and route:** gpu mode returns 200; `tick` and the time range are validated; the selection-epoch 409 is kept.
5. **Hot path:**
   - no capacity growth over 120 frames;
   - no glyph outside `drawRect`;
   - device-pixel snapping at 1x/1.5x/2x;
   - the label gate and the budget.
6. **`heatmap-ab.sh`:** a label step, plus a `/walls` JSON diff.

## 8. Risks

- 1h near composition cost: mitigated by the clip, the cache and stop-when-no-veil; the bench gate catches a miss.
- Chunk eviction: labels can arrive late.
- A generation mismatch during a revision: key on generations.
- A one-frame lag of the drawn tick at transitions.
- Glyph-cap drops on dense books.
- Hot-path care (AGENTS.md section 5).

## 9. Owner decisions (2026-10-01)

1. **Text size.** A label appears on every coloured cell (above the range filter's low handle) where its text fits at 12 px plus padding. As cells grow, the text grows only up to 15 px and never larger. No shrink-to-fit below 12 px. All of this is tweakable later.
2. **Liquidity range filter, style and currency.**
   - One two-handle range slider. Its ends span the liquidity present in the current view, on a log scale.
   - The low handle hides cells below it: no colour and no label.
   - The high handle is the colour saturation point.
   - In gpu mode it replaces the separate liquidity-threshold and sensitivity controls; the range persists per chart.
   - Labels use 3 significant digits and show currency by default (`$1.24M`, `$847k`), with a toggle to the asset amount (`12.5 BTC`).
3. **Walls.**
   - The default scope is the user's current viewport (the visible time range plus a price margin of one view height each way).
   - A model or agent can request an explicit period (`from_ms`/`to_ms`) and an optional `tick`.
   - Computed only on request.
   - Ranked by peak resting size (legacy definition), each with mean size, first/last seen, columns persisted (persistence) and notional, so a model can tell a long-standing wall from a brief spoof.
4. **On-chart wall markers:** deferred (a later feature, for example top-5 tags on the right edge).

## 10. S7a implementation and hand-off (2026-10-02)

Implemented on `lt-astra/s7a-cell-query`. No renderer label layout or settings UI is included; those remain S7b. Core remains free of GUI Qt. The node's clip extraction uses reused scratch vectors and introduces no signals or QObject work in layout.

API for S7b:
- `controller->cellQuery()` is owned by the controller on heatmap-data. Queue `requestLabels(LabelRequest, drawnSpans, drawnLive)` to that thread. `LabelRequest` carries a monotonically increasing serial, immutable picture versions, tf/tick/scale, first bucket/bin, columns/rows and asset. The window limit is 16,000 cells.
- `latestLabels()` is safe to read across threads and returns `shared_ptr<const LabelCells>`. Connect `labelsChanged` with `Qt::QueuedConnection`. Cells are row-major, highest price first, with the exact dominant double, GPU word, and fixed 48-byte USD/asset buffers. USD uses the cell midpoint; both strings round to three significant digits. S7b must check the returned picture/tick/serial and apply its hold/crossfade gate.
- `LabelWindowBuilder` owns a 32 MiB tick-free composition LRU and reuses historical cells for live-only revisions. It peeks exact drawn generations; missing sealed generations are re-wanted at label rank only after CPU ledger admission. Queries use the existing bounded pool, one job per controller, a conservative 64 MiB scratch reservation and retained-cache/result charges. A walls request interrupting a label reload restarts the pending label afterwards.
- `scanWalls` shares this oracle, batches at most 16,000 cells, retains at most 500 level accumulators plus the ranked limit, and accepts at most eight queued requests per controller. It uses held data only. JSON adds `renderer`, `tick`, requested `range`, `unknownRows` and per-wall `rank`; persistence fields and the selection-epoch 409 remain. The canonical route details are in `docs/AGENT_API.md`.

Benchmark: `build/mac-clang/tests/render/heatmap_cell_query_bench /Volumes/T7/sentinel-data/recording`, local transport, read-only, no live server. 120 columns x 100 rows (12,000 cells), pinned completed end `1790913600000`; 41 warm samples per case.
