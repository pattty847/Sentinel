### **Sentinel — Windows Build Guide (MSVC + Qt6 + vcpkg)**

This guide describes the **official** way to build Sentinel on Windows using:

- **MSVC 2022 (Build Tools or full VS 2022)**
- **Qt 6.9.3 (msvc2022_64)** (or compatible Qt6 MSVC build)
- **vcpkg** (manifest mode)
- **CMake presets** with the `Visual Studio 17 2022` generator

---

### **1. Prerequisites**

- **Windows 10 or later** (64‑bit)
- **CMake 3.22+**
- **Git**
- **Visual Studio 2022** (any of):
  - Visual Studio 2022 **Community / Professional / Enterprise** with:
    - *Desktop development with C++*
  - **OR** *Visual Studio 2022 Build Tools* with:
    - MSVC C++ toolset
    - Windows 10 SDK
- **vcpkg** (installed anywhere, e.g. `C:\dev\vcpkg`)
- **Qt 6.x MSVC** (recommended: **6.9.3 msvc2022_64** from the Qt online installer)

---

### **2. Required Environment Variables**

Set these once in a regular (non‑VS) PowerShell or cmd, then restart your terminal:

- **VCPKG_ROOT** — path to your vcpkg clone
- **QT_MSVC** — path to your Qt MSVC installation root

Examples (PowerShell):

```powershell
setx VCPKG_ROOT "C:\dev\vcpkg"
setx QT_MSVC    "C:\Qt\6.9.3\msvc2022_64"
```

Verify:

```powershell
echo $env:VCPKG_ROOT
echo $env:QT_MSVC
```

> **Note:** You do **not** need to open a special “Developer Command Prompt”.  
> The CMake preset uses the **Visual Studio 2022 generator**, which configures MSVC automatically.

---

### **3. One‑Shot Setup (Recommended)**

From the repo root:

```powershell
cd path\to\Sentinel
scripts\setup-windows.ps1
```

This script will:

- Verify:
  - Visual Studio 2022 C++ tools + Windows 10 SDK
  - `VCPKG_ROOT` and `QT_MSVC` (and that `windeployqt.exe` exists)
- Run:
  - `vcpkg install --triplet x64-windows` (manifest-driven install)
- Generate:
  - A minimal `CMakeUserPresets.json` if it doesn’t exist
- Configure:
  - `cmake --preset windows-msvc-vs`

If anything is missing, the script exits with a clear error message.

---

### **4. Manual Build Commands**

If you prefer to run things manually after the initial setup:

From the repo root:

```powershell
# Configure (Visual Studio 2022 generator, x64, vcpkg + Qt)
cmake --preset windows-msvc-vs

# Build Debug configuration
cmake --build --preset windows-msvc-vs --config Debug
```

The Visual Studio solution and binaries will live under:

- `build/windows-msvc-vs/`

The main GUI executable (Debug) will be at:

- `build/windows-msvc-vs/apps/sentinel_gui/Debug/sentinel_gui.exe`

---

### **5. Qt Deployment (windeployqt)**

The `sentinel_gui` target has an automatic post‑build step on Windows:

- After each build of `sentinel_gui`, CMake runs:
  - `windeployqt.exe $<TARGET_FILE:sentinel_gui>`
- `windeployqt` is resolved from:
  - `"$env:QT_MSVC\bin\windeployqt.exe"`

Result:

- All required Qt DLLs and plugins are deployed next to `sentinel_gui.exe`.
- You can **double‑click the EXE** in Explorer and the app should launch without additional setup.

If deployment fails, check:

- `QT_MSVC` points at the correct Qt MSVC build (e.g. `C:\Qt\6.9.3\msvc2022_64`)
- `bin\windeployqt.exe` exists under that directory

---

### **6. Opening in Visual Studio**

After running the configure step (via the setup script or `cmake --preset windows-msvc-vs`), you can open:

- `build/windows-msvc-vs/Sentinel.sln`

Notes:

- The solution is **generated by CMake**; do not edit project settings directly in Visual Studio.
- Use:
  - `ALL_BUILD` to build everything
  - `sentinel_gui` as the startup project for the main GPU terminal

---

### **7. Common Issues**

- **CMake can’t find Qt6:**
  - Ensure `QT_MSVC` is set and points to the **MSVC** Qt kit, not MinGW.
  - Example: `C:\Qt\6.9.3\msvc2022_64`

- **Boost / OpenSSL / jwt-cpp not found:**
  - Ensure `VCPKG_ROOT` is set correctly.
  - Re-run:
    - `scripts\setup-windows.ps1`
    - or manually: `vcpkg install --triplet x64-windows` from the repo root.

- **Pthread or MinGW/MSYS2 noise:**
  - The current configuration is pure **MSVC + vcpkg + Qt6**.
  - There should be **no MinGW/MSYS2** paths involved; if you see such errors, check your global PATH for stale toolchains.

---

### **8. Expected Happy Path**

On a clean Windows machine with prerequisites installed, the full flow is:

```powershell
git clone https://github.com/you/Sentinel.git
cd Sentinel

setx VCPKG_ROOT "C:\dev\vcpkg"
setx QT_MSVC    "C:\Qt\6.9.3\msvc2022_64"
start powershell  # new shell to pick up env vars

cd path\to\Sentinel
scripts\setup-windows.ps1
cmake --build --preset windows-msvc-vs --config Debug

.\build\windows-msvc-vs\apps\sentinel_gui\Debug\sentinel_gui.exe
```

If this sequence does not produce a working GUI, capture the full console output and logs and we can tighten the build pipeline further.

### **9. MSVC Toolchain Notes (Dev Prompt vs Normal Shell)**

- **Visual Studio generator (`windows-msvc-vs`)**:
  - CMake uses `vswhere.exe` + the `Visual Studio 17 2022` generator.
  - It finds `cl.exe`, `link.exe`, and the Windows SDK automatically.
  - **You do _not_ need** to run a special “x64 Native Tools” prompt for this preset.

- **Ninja generator (`windows-msvc-ninja`, optional for IDE tooling)**:
  - Ninja does **not** know where MSVC lives by itself.
  - You must either:
    - Run from **“x64 Native Tools Command Prompt for VS 2022”**, which calls `vcvars64.bat` / `VsDevCmd.bat`, or
    - Pass explicit compilers, e.g. `-DCMAKE_C_COMPILER=cl -DCMAKE_CXX_COMPILER=cl`.
  - In Sentinel this preset is only used to generate a `compile_commands.json` for clangd, not for normal builds.

Typical places to find the dev environment scripts (do not hardcode in CMake; this is just for manual use):

- **Build Tools**:
  - `"%ProgramFiles(x86)%\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat"`
- **VS 2022 Community** (if installed):
  - `"%ProgramFiles(x86)%\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"`

You can always avoid the dev prompt entirely by sticking to the `windows-msvc-vs` preset for configure/build, and reserve the Ninja preset for editor integration only.
